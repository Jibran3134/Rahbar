## Reproduce the baseline

On another Windows checkout, install a verified Python 3.12.10 runtime first. The normal command is py -3.12 -m venv .venv when the launcher can find it; otherwise invoke the explicit runtime path with -m venv.

~~~powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --disable-pip-version-check --no-cache-dir -c docs/evidence/app/sprints/S00-constraints.txt -r api/requirements-dev.txt -r indexer/requirements-dev.txt
.\.venv\Scripts\python.exe -m pip check
Push-Location api
..\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
..\.venv\Scripts\python.exe -m mypy app
Pop-Location
Push-Location indexer
..\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
..\.venv\Scripts\python.exe -m mypy pipeline
Pop-Location
.\.venv\Scripts\python.exe -m ruff check api indexer eval corpus
~~~

Check each native exit code when automating. Constraints capture this tested Windows/Python baseline and are not a substitute for later Linux image/CI validation. The repository only pins direct requirements; resolved transitives are preserved in this evidence snapshot.

On this machine use .\.venv\Scripts\python.exe directly. There is no need to activate the venv, use Ubuntu or change global Python. As with ordinary venvs, regenerate it if the repository path moves. Do not run the nested base interpreter directly for ordinary development.
