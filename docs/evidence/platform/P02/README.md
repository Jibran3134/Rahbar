# P02 - Real persistent minikube deployment

Initial deployment PASS. The dedicated rahbar profile uses Calico, Ingress and metrics-server; the default k3d-civicpulse-ci context was preserved. Strict UTF-8-rendered manifests validated all 31 base resources (CI overlay: 38). The initial image tag platform-p01 was functional but subsequently failed vulnerability scanning; P03 records security remediation rather than calling these images release-ready.

All seven public files downloaded in the init container matched the original manifest. The Linux indexer completed with 813 chunks in 306 seconds. Three API replicas became ready only after publication. Actual Ingress returned the current makeup-week withdrawal deadline with its valid citation and refused an absent hostel deadline. Native outputs: ingress-queries.json, fetch.txt, indexer.txt, pods.txt, endpoints.txt, hpa.txt and top.txt. Initial apply.log records native exit 0. The deploy helper was subsequently renamed from scripts/platform.py to scripts/deploy.py to avoid shadowing the standard Python platform module.

Thirty-five live samples captured cgroup memory.peak up to 343830528 bytes (327.902 MiB), including OCR children, against memory.max 1610612736 bytes (1536 MiB). Samples and simultaneous kubectl top output are in indexer-memory.json. The finite-workload observed headroom is 1208.098 MiB; it is not a universal memory guarantee. Cluster recovery after Docker restart retained the data and recovered readiness; further controlled recovery/network/rollout checks remain P04. Human review and remote release evidence remain pending.
